Chrome-ARF 文档

Auto Refresh Framework · 完整使用指南

快速开始

Chrome-ARF 是一个基于 Chrome DevTools Protocol (CDP) 的自动刷新框架，无需安装浏览器扩展即可实现页面定时刷新。

安装与运行

  1. 确保已安装 Python 3.6+ 和 Google Chrome 浏览器
  2. 安装依赖：pip install flask requests websocket-client
  3. 运行程序：python refresh_web.py
  4. 打开浏览器访问：http://localhost:5000

核心特性

零配置启动

自动检测 Chrome 路径和可用端口，开箱即用

智能标签页

自动识别当前活跃标签页进行刷新

安全本地

仅使用本地调试协议，无需网络权限

Web 管理

直观的 Web 界面，实时状态监控

技术架构

工作原理

Chrome-ARF 通过以下步骤实现自动刷新：

  1. 以远程调试模式启动 Chrome（--remote-debugging-port）
  2. 通过 HTTP API 获取所有打开的标签页列表
  3. 使用 WebSocket 连接到目标标签页
  4. 发送 CDP 命令 Page.reload 执行刷新

CDP 协议说明

Chrome DevTools Protocol 是 Chrome 浏览器提供的调试协议，允许程序化控制浏览器。本工具使用的端点：

  • /json - 获取所有标签页信息
  • /json/version - 获取浏览器版本信息
  • WebSocket - 与标签页建立双向通信

API 接口

Chrome-ARF 提供以下 REST API 接口：

接口 方法 说明
/api/status GET 获取当前状态（Chrome连接、刷新状态、日志等）
/api/launch POST 启动 Chrome 调试实例
/api/start POST 开始自动刷新（参数：interval）
/api/stop POST 停止自动刷新
/api/clear POST 清除日志和计数
/api/open-browser POST 打开普通浏览器窗口（参数：url）

响应格式

{
  "success": true,
  "status": "已连接",
  "running": false,
  "count": 42,
  "current_tab": {
    "title": "Example Page",

配置选项

刷新间隔

支持范围：5秒 - 3600秒（1小时）

  • 快捷预设：30秒、1分钟、5分钟、10分钟
  • 自定义输入：直接输入数字即可

Chrome 启动参数

--remote-debugging-port=9222   # 调试端口
--user-data-dir=...            # 用户数据目录
--remote-allow-origins=*       # 允许跨域连接
--no-first-run                 # 跳过首次运行向导
--no-default-browser-check     # 跳过默认浏览器检查

端口自动切换

如果默认端口 9222 被占用，程序会自动尝试 9223-9232 范围内的可用端口。

命令行版本

除了 Web 界面，还提供命令行版本：

基本用法

# 默认 60 秒间隔
python refresh-final.py

# 自定义间隔（秒）
python refresh-final.py 30

环境检测

程序启动时会自动检测：

  • Python 版本（需要 3.6+）
  • pip 是否可用
  • Chrome 浏览器路径
  • 端口可用性
  • 代理环境配置

常见问题

Q: Chrome 启动失败怎么办？

A: 检查 Chrome 是否正确安装，尝试手动指定 Chrome 路径，或关闭已有的 Chrome 实例。

Q: 无法连接到标签页？

A: 确保 Chrome 以调试模式启动，检查防火墙设置，尝试更换端口。

Q: 刷新间隔不准确？

A: 实际间隔可能有 ±1秒 的误差，这是正常现象。网络延迟也可能影响刷新时间。

Q: 支持哪些浏览器？

A: 目前仅支持 Google Chrome 和 Chromium 内核的浏览器。
